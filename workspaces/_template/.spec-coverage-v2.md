### CRITICAL (Must fix before any deployment)

1. **No POST /api/v1/email/inbound endpoint** -- The reply-to-resolve processor logic exists but SendGrid webhooks have no HTTP entry point. The inbound email fix is half-implemented.

2. **FK constraints use CASCADE, not RESTRICT** -- Deleting a tenant cascades to delete audit entries, violating both the spec and PDPA audit immutability requirements.

3. **Tenant schema isolation not enforced at query layer** -- Schemas are created during signup but DataFlow express operations run against the public schema, not tenant-specific schemas. Cross-tenant data leakage is possible.

### HIGH (Must fix before launch)

4. **Audit trail covers 2 of 8 required state transitions** -- message_classified, rag_retrieved, response_auto_sent, escalation_routed, backup_notified have no audit writers.

5. **PDPA consent not collected at signup** -- Singapore legal requirement unmet.

6. **No AI classification/RAG/auto-response pipeline** -- Core product value has no implementation.

7. **No WhatsApp integration** -- No BSP client, no templates, no session management.

8. **Audit immutability not DB-enforced** -- No triggers preventing UPDATE/DELETE on audit_entries.

9. **6 composite indexes missing** -- Spec requires specific composite indexes; only single-column indexes exist.

10. **Erasure is soft overwrite, not hard delete** -- Spec requires hard deletion of Contact, Message, Response, RoutingOutcome records. Code only overwrites PII fields.

### MEDIUM (Should fix before launch)

11. Embedding dimension mismatch (spec 1536, code 768).
12. Email retry window too short (35 min vs spec 1 hour).
13. Contact identity resolution incomplete (email only, no phone or name+domain).
14. No data portability export or breach response.
15. Routing flywheel has no engine (model exists, no aggregation job).
16. Signup defaults to "starter" instead of "free" tier.
17. Escalation model missing 5 spec-required fields (thread_key, channel, ai_summary, routing_reason, suggested_response).
18. No simultaneous notification for urgent/critical escalations.
19. No plan enforcement or billing logic.
