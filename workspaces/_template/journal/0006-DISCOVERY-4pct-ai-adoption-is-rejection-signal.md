# DISCOVERY: OOO coverage is a new category, not a subcategory of existing AI tools

**Type:** DISCOVERY
**Date:** 2026-04-19
**Author:** co-authored (AI analysis + human correction)

## Finding

The 4% AI adoption statistic is about AI tools broadly (helpdesks, CRMs, email assistants, IT tools). It does NOT apply to the OOO coverage category — because that category doesn't exist yet. No product has been built and marketed specifically for "autonomous OOO coverage."

The existing competitive landscape is a collection of fragmented silos:

- Notification tools (WhatsApp Business, AutoResponder.ai) — tell you what happened, don't resolve anything
- Task trackers (Trello, Asana, Notion) — capture what needs to be done, don't主动 get it done
- AI email tools (Superhuman, SaneBox) — help you reply faster when present, don't cover when absent
- Phone answering services (Smith.ai) — handle voice, not cross-channel WhatsApp/email

Each addresses one narrow slice. None resolves the full problem: primary goes away, messages pile up, tasks go untracked, nothing gets completed.

## Why This Changes the Analysis

The earlier framing ("4% adoption = rejection signal") was wrong. It applied a statistic about existing AI tool categories to a category that has never been built. The challenge is not "break through existing skepticism." The challenge is **category creation** — making buyers aware that "AI that covers for me completely while I'm away" is a thing they should evaluate.

## Product Definition (Updated)

The Sequor is the only product that:

1. Reads incoming messages across WhatsApp and email
2. Resolves routine queries autonomously by retrieving from internal records
3. Tracks and completes tasks while the primary is away
4. Answers factual questions from internal documents ("Did I sign up for the event tomorrow?") by pulling records, not forwarding the question

This is not competing in an existing category. It is creating a new one.

## Implication for Brief

The "Competitor Gap" section should be rewritten. The gap is not "SleekFlow doesn't do RAG from internal docs." The gap is: no product exists that does all four of the above. The brief's USP should lead with category creation, not feature comparison.
