## Per-surface verdicts

- **auth**: FAIL — forgeable-token dev-secret fallback (CRITICAL); no aud/iss claims; role derived but largely unused for authz.
- **webhook-sig**: PARTIAL — WhatsApp/Meta HMAC correct (constant-time, verified before processing); Stripe correct (library `construct_event`+idempotency); SendGrid fragile/likely-broken + no replay; all skip in dev mode.
- **secrets**: PASS — no hardcoded API keys/tokens; all from `.env`/`Settings`. Sole exception: JWT dev-secret constant (counted under auth). Logs use masking helpers.
- **injection (SQL)**: PASS — parameterized throughout; `validate_identifier` guards the only f-string DDL (schema/table names from UUIDs).
- **injection (prompt)**: PARTIAL — no separation on the auto-send path (MEDIUM).
- **encryption**: FAIL — message content plaintext vs spec claim; fail-open dev-mode default.
- **PDPA / data-handling**: FAIL — erasure incomplete + over-deletion; message content neither encrypted nor erased; schema isolation not enforced. Audit trail (`db/audit.py`) clean (UUID-only); input validation (`schemas.py`) + email templates solid.
- **rate-limit**: PARTIAL — present but fail-open at capacity + serverless-ineffective.
- **tenant-isolation**: FAIL — column-based vs spec's schema mandate; integrity hinges on forgeable JWT.

Counts: 1 CRITICAL, 6 HIGH, 5 MEDIUM, 3 LOW.
